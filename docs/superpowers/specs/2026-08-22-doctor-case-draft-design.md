# 病例端病例草稿设计

## 目标

支持医生在新建病例时保存草稿，也支持在病例中心通过弹窗编辑草稿、提交审核或删除草稿。

前后端共同完成以下能力：

- `POST /doctor/cases/draft`：新建或更新病例草稿。
- `POST /doctor/cases`：提交病例。新建时不带 `id`，提交草稿时带已有病例 `id`。
- `GET /doctor/cases`：病例分页，支持 `draft` 状态筛选。
- `GET /doctor/cases/{id}`：读取病例详情，编辑弹窗打开时回填草稿。
- `DELETE /doctor/cases/{id}`：删除病例，仅允许删除当前医生自己的草稿，使用后端逻辑删除。

后端会在带 `id` 的保存、提交和删除请求中校验病例归属；保存和提交要求当前状态为草稿，删除额外要求当前状态为草稿。

## 页面与路由

保留新建病例的提交页面，草稿编辑不再使用提交页面路由：

- 新建：`/cases/submit`
- 编辑草稿：病例中心弹窗

病例中心操作列仅对 `status === 'draft'` 的记录显示“编辑”和“删除”按钮。其他状态保留详情查看入口，不显示这两个操作。

## 新建页面

- 页面标题为“提交病例”。
- 显示“保存草稿”和“提交病例”。
- “保存草稿”调用 `saveDraftCase`，请求不带 `id`，成功后返回病例中心。
- “提交病例”调用 `submitCase`，请求不带 `id`，成功后返回病例中心。

## 草稿编辑弹窗

- 病例中心点击草稿“编辑”后打开弹窗。
- 弹窗打开时调用 `getCaseDetail(id)`，而不是只依赖列表行数据，确保回填内容是最新的。
- 弹窗回填标题、备注和已有附件。
- 弹窗显示“取消”和“提交病例”，不显示“保存草稿”；编辑中的草稿通过提交接口转为待审核。
- 提交请求携带 `id`，成功后关闭弹窗并刷新病例列表。
- 详情加载失败或返回非草稿时，关闭弹窗并显示错误提示。

## 删除草稿

- 仅草稿行显示删除按钮。
- 删除前显示确认框。
- 确认后调用 `DELETE /doctor/cases/{id}`，成功后刷新当前列表。
- 后端再次校验归属和草稿状态，不能仅依赖前端按钮隐藏。
- 删除使用实体上的逻辑删除字段，不物理删除数据库记录。

## API 封装

在 `src/api/doctor/cases.js` 中维护以下接口封装：

- `saveDraftCase(data)` -> `POST /doctor/cases/draft`
- `submitCase(data)` -> `POST /doctor/cases`
- `getCasePage(params)` -> `GET /doctor/cases`
- `getCaseDetail(id)` -> `GET /doctor/cases/{id}`
- `deleteCase(id)` -> `DELETE /doctor/cases/{id}`

## 状态展示

在 `src/utils/doctorCase.js` 中增加：

- 状态页签：`{ key: 'draft', label: '草稿' }`
- 状态标签映射：`draft -> 草稿`
- 状态样式映射：草稿使用信息色或默认色。

病例中心继续优先展示后端返回的 `statusDesc`，没有描述时使用前端状态映射兜底。

## 表单与附件

提交页和编辑弹窗复用现有附件上传规则和上传接口。

编辑草稿时，详情中的已有附件转成页面附件项，但不携带待上传的原始文件，因此不会重复上传。新选择的附件继续立即上传；提交 payload 使用已有附件与新增附件的合并结果。

删除附件时，只从当前 payload 中移除对应附件。删除已有附件不需要额外调用删除接口，因为后续提交会以当前附件列表覆盖病例附件。

提交或保存按钮在以下条件下不可用或提示用户：

- 标题为空。
- 仍有附件上传中。
- 附件上传失败或页面附件与已上传附件数量不一致。

保存草稿复用同样的表单和附件校验，但标题仍作为必填字段处理，避免产生无法识别的草稿记录。

## 数据流

1. 病例中心加载分页数据。
2. 草稿记录显示“编辑”和“删除”入口。
3. 医生点击编辑后打开弹窗并读取病例详情。
4. 弹窗回填表单及已有附件。
5. 医生新增或删除附件，页面维护当前附件集合。
6. 新建页面根据按钮选择调用保存草稿或提交接口。
7. 编辑弹窗调用带 `id` 的提交接口。
8. 删除草稿调用删除接口。
9. 请求成功后关闭弹窗或刷新病例中心，列表显示最新状态。

## 错误处理

继续使用现有 request 封装和 `ElMessage` 错误提示。

- 详情加载失败：关闭弹窗并显示请求错误。
- 编辑对象不是草稿：关闭弹窗并显示“当前病例不可修改”。
- 删除取消：不显示错误提示，也不刷新列表。
- 保存、提交或删除失败：保留当前内容或列表状态，解除 loading 状态。
- 防止操作过程中重复点击。

## 测试与验证

实现后至少验证：

- `doctorCase` 状态列表、标签和样式映射包含 `draft`。
- API 方法使用正确的 URL、HTTP 方法和 payload，包含删除接口。
- 新建页面可分别触发保存草稿和提交病例。
- 草稿弹窗读取详情、回填并以 `id` 提交。
- 非草稿记录不显示编辑和删除按钮。
- 后端仅允许本人删除草稿，非草稿和他人病例均被拒绝。
- 病例端使用 Node.js `22.23.2` 执行 `yarn test`。
- 病例端使用 Node.js `22.23.2` 执行 `yarn build`。
- 后端执行 DoctorCaseService 定向测试。

## 范围边界

本次不实现已提交病例的再次编辑，不增加附件独立删除接口，不改变病例提交后的状态流转。
