# 医生端病例草稿设计

## 目标

支持医生在新建病例时保存草稿，也支持从病例中心打开草稿并提交审核。

本次前端只适配已有后端接口：

- `POST /doctor/cases/draft`：新建病例草稿。
- `POST /doctor/cases`：提交病例。新建时不带 `id`，提交草稿时带已有病例 `id`。
- `GET /doctor/cases`：病例分页，支持 `draft` 状态筛选。
- `GET /doctor/cases/{id}`：读取草稿详情并回填编辑表单。

后端会在带 `id` 的提交请求中校验病例归属及当前状态必须为草稿，并将状态更新为待审核。

## 页面与路由

继续复用现有提交页面和路由：

- 新建：`/cases/submit`
- 编辑草稿：`/cases/submit?id=<caseId>`

病例中心操作列仅对 `status === 'draft'` 的记录显示“修改”按钮。点击后进入带 `id` 的提交页面。其他状态保留详情查看入口，不显示修改操作。

提交页面根据查询参数区分两种模式：

### 新建模式

- 页面标题为“提交病例”。
- 显示“保存草稿”和“提交病例”。
- “保存草稿”调用 `saveDraftCase`，请求不带 `id`，成功后返回病例中心。
- “提交病例”调用 `submitCase`，请求不带 `id`，成功后返回病例中心。

### 草稿编辑模式

- 页面加载时调用 `getCaseDetail(id)`。
- 回填标题、备注和已有附件。
- 仅显示“提交病例”，不显示“保存草稿”。
- 提交调用 `submitCase`，请求携带 `id`，成功后返回病例中心。
- 如果详情返回的状态不是 `draft`，提示当前病例不可编辑并返回病例中心。

## API 封装

在 `src/api/doctor/cases.js` 中增加保存草稿方法，保持现有请求封装风格：

```js
export function saveDraftCase(data) {
  return request({
    url: '/doctor/cases/draft',
    method: 'post',
    data
  })
}
```

`submitCase` 保持原有接口和 payload 结构，只在草稿编辑模式增加 `id`。

## 状态展示

在 `src/utils/doctorCase.js` 中增加：

- 状态页签：`{ key: 'draft', label: '草稿' }`
- 状态标签映射：`draft -> 草稿`
- 状态样式映射：草稿使用信息色或默认色。

病例中心继续优先展示后端返回的 `statusDesc`，没有描述时使用前端状态映射兜底。

## 表单与附件

提交页保留现有附件上传规则和上传接口。

编辑草稿时，详情中的已有附件转成页面附件项，但不携带待上传的原始文件，因此不会重复上传。新选择的附件继续立即上传；提交 payload 使用已有附件与新增附件的合并结果。

删除附件时，只从当前 payload 中移除对应附件。删除已有附件不需要额外调用删除接口，因为后续提交会以当前附件列表覆盖病例附件。

提交按钮在以下条件下不可用或提示用户：

- 标题为空。
- 仍有附件上传中。
- 附件上传失败或页面附件与已上传附件数量不一致。

保存草稿复用同样的表单和附件校验，但标题仍作为必填字段处理，避免产生无法识别的草稿记录。

## 数据流

1. 病例中心加载分页数据。
2. 草稿记录显示“修改”入口。
3. 医生进入编辑路由后读取病例详情。
4. 页面回填表单及已有附件。
5. 医生新增或删除附件，页面维护当前附件集合。
6. 新建模式根据按钮选择调用保存草稿或提交接口。
7. 编辑模式调用带 `id` 的提交接口。
8. 请求成功后返回病例中心，病例列表重新加载时显示最新状态。

## 错误处理

继续使用现有 request 封装和 `ElMessage` 错误提示。

- 详情加载失败：显示请求错误，并返回病例中心。
- 编辑对象不是草稿：显示“当前病例不可修改”，返回病例中心。
- 保存或提交失败：保留当前表单内容，不跳转，解除按钮 loading 状态。
- 防止保存或提交过程中重复点击。

## 测试与验证

实现后至少验证：

- `doctorCase` 状态列表、标签和样式映射包含 `draft`。
- API 方法使用正确的 URL、HTTP 方法和 payload。
- 新建页面可分别触发保存草稿和提交病例。
- 草稿详情可回填并以 `id` 提交。
- 非草稿记录不显示修改按钮。
- `yarn test`
- `yarn build`

## 范围边界

本次不新增后端接口、不修改后端状态流转、不实现已提交病例的再次编辑，也不增加独立编辑页面或弹窗编辑体系。
